## 1. 一页纸执行摘要

### 1.1 Definition of Done（6 条同时满足 = MVP 会议目标达成）

1. P0-SEC-1：`customer-rank` SQL 参数化 + 非法日期拒查。  
2. P0-AUTH-1：会话/审计**书面路线**（Redis+审计 或 Demo 闸门）已立项入 `docs/` 或 ADR。  
3. 三页口径块：`/fact-event`、`/receivable`、`/payable` 可见。  
4. `/help` 上线：免责 + 口径 + 版本号。  
5. `/customer-analysis`：用途说明 + 页脚声明。  
6. 首页 **≥2** 条可点击钻取带 query（见规格 §4 E3）。

### 1.2 Epic 一览（规格 §2）

| Epic | 名称 | 优先级 |
|------|------|--------|
| E0 | 客户排名接口安全 | P0 |
| E1 | 帮助与免责 | P0 |
| E2 | 口径说明块三页 | P0 |
| E3 | 首页钻取 MVP | P1 |
| E4 | 客户分析用途化 | P1 |
| E5 | 项目本会讨论焦点 | P2 |
| E6 | 侧栏 IA 分组 | P2 |
| E7 | Boss 会议清单（轻量） | P2 |

## 3. V2 相对 V1 的定位变化

| 维度 | V1（当前实现主线） | V2（目标产品） |
|------|-------------------|----------------|
| 第一叙事 | Fact → 指标 → 看板 | **经营对话** → 责任与目标 → 数字印证 |
| 首页 | 经营数据总览 | **总览 + 钻取 + 例会入口** |
| 组织 | 隐含全公司一层 | **项目 = 最小经营体** → 二期组织/巴 |
| 排行榜/分析 | 能力已有 | **目的化**文案 + 安全 |
| 安全与信任 | Demo 级 | **信任底座**（参数化 SQL、会话路线） |
| 口径 | 多模块并存 | **显性声明**（页面块 + `/help`） |

## 4. 重新设计会议：三方决议

### 4.1 产品团队（40%）

- IA 分组（侧栏 `el-sub-menu`）、首页钻取、P0 排期、口径块位置与版本。

### 4.2 Boss（20%）

- 首页「一眼」不删减；**E7 会议清单**（逾期、余额、待决策占位）；免责声明由 Boss 确认措辞。

### 4.3 稻盛和夫式经营（40%）

- 项目页反省模板；排行榜非奖惩；信任 P0 与哲学一票否决同级。

---

## 5. V2 核心产品模型

保留 **Fact →（归因扩展）→ Metrics → Decision**；用户叙事：**经营意图 → 可对谈 Status → 人工 Action**（不承诺自动决策计算，与 [product-design.md](./product-design.md) Agent 边界一致）。
