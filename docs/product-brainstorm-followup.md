## 2. 头脑风暴 — 边界澄清（收敛为「三层边界」）

### 2.1 我们**明确要做**的（核心圈）

- **经营事实录入与可追溯**：`fact_event` 为主轴，冲正/状态可解释。  
- **项目维度的盈亏与结构成本**：支撑「把项目当最小经营体」对话。  
- **资金侧辅助视图**：应收/应付与**文案声明**的口径关系，不冒充总账。  
- **管理层一眼摘要 + 可钻取**：服务周会开场，不服务月末结账替代。

### 2.2 我们**明确不做**（外圈 — 写进对外话术与 `/help`）

- 不替代 **总账 / 税务申报 / 审计底稿**。  
- 不承诺 **多组织法定合并、阿米巴内部定价、人事绩效**。  
- 不输出 **自动经营决策**（AI 可辅助录入与解释，不可替人拍板 —— 与 V1 Agent 边界一致）。

### 2.3 **灰区**（必须二选一写清，否则边界永远糊）

| 灰区 | 会上建议 | 规格/文档动作 |
|------|----------|----------------|
| 客户排名 / Top N | 只做「改善讨论」工具，不做 KPI 引擎 | 已部分在 E4；**加强**首页与客户页同一套话术引用 |
| 与 Excel 并行 | 谁是「经营讨论」的权威？ | `/help` 增加「建议以本系统为经营例会数字底座，Excel 为个人草稿」**或** 反写由财务定 |
| Demo 鉴权 | 能否对外演示含真实数据？ | P0-AUTH-1 必须选 B「仅 Demo」或 A「上线路线」**一条写到纸面** |

| 不合理点 | 调整方向（产品） | 与现规格关系 |
|----------|------------------|--------------|

## 4. 头脑风暴 — 产品优势「弱」怎么补强（叙事，不是堆功能）

### 4.1 诚实 SWOT（会上用，不对外原样贴）

- **S**：轻、快、领域边界清楚；项目 P&amp;L + 预算实际已形成差异化组合；Vue+Spring 易迭代。  
- **W**：无组织维度、无强鉴权、部分聚合直 SQL、与 ERP 重叠感。  
- **O**：中小团队「先谈数字再谈系统」、阿米巴/项目制渗透；Agent 辅助录入。  
- **T**：免费表格 + 大厂 BI；若边界继续糊，**必被表格打败**。

### 4.2 一句话价值主张（三选一，产品定稿其一）

1. **「周会数字底座」**：十分钟对齐收入/成本/逾期，钻到项目与客户，**不替代**结账。  
2. **「项目经营体沙盘」**：一屏看清项目结构成本与预算执行，**支撑反省会**。  
3. **「轻量经营事实系统」**：比 Excel 多一层状态与口径，比 ERP 少十层重量。

**建议**：对外主叙事用 **①**，对内研发用 **②** 对齐 backlog。

### 4.3 「弱」的纠偏动作（不做大功能也能变强）

- 首页首屏加 **一句价值主张**（与顶部副标题区分）。  
- `/help` 首段用 **非技术语言** 重复三层边界 §2。  
- 案例页（可 PPT）：**一项目一周会** 截图故事线（文档或 `docs/` 下 `product-story-onepager.md` 二期）。

## 7. 5W2H 与「落地真实性」说明（门禁）

- **5W2H**：What / Why / Who / When / Where / How / How much（How much 在本仓库中指**验收粒度**：如「1 条 curl + 1 张截图」或「PR 链接」）。  
- **落地真实性**：每条 BR 的 **How** 必须包含**可复现验证步骤**（不得仅写「完成开发」）。  
- **会议收敛通过**：PO 勾选规格 **第 17 节** 各 BR 的「验证证据」已全部完成，且与 Git 提交或构建产物一致。
