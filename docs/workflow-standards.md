# 项目工作流程规范（长期记忆）

## 🎭 角色切换机制

**自动角色切换：**
- 任务推进时自动切换角色
- 架构师 → 开发工程师 → 产品 → 业务专家 → 测试工程师
- 根据任务类型自动选择最合适的角色

---

## 📅 每日工作流程

### 🌙 每天晚上：代码审查会议

**时间：** 每天晚上（自动执行定时任务）

**参与人员：**
- 开发工程师（全体）
- 产品经理
- Boss

**审查内容：**
1. 当天的代码变更
2. 功能实现情况
3. 技术方案合理性
4. 进度是否符合预期

**审查结果：**
- ✅ 通过：继续按计划执行
- ⚠️ 有问题：调整后续任务内容和分配

**输出：**
- 每日审查报告
- 问题清单
- 调整方案

---

### 🌅 每天早上：产品方向会议

**时间：** 每天早上

**参与人员：**
- 产品经理
- Boss

**会议内容：**
1. 产品方向是否需要调整
2. 领域模型是否需要变更
3. 功能优先级是否需要调整
4. 市场反馈和竞品分析

**会议结果：**
- ✅ 无变更：继续按计划执行
- ⚠️ 有变更：通知全体并进行审查

**输出：**
- 产品方向决策
- 变更通知
- 调整方案

---

## 🔄 阶段性交付机制

### 交付周期：2天

**Day 1-2：第一阶段**
- 开发任务
- 阶段性交付
- 整体审查

**Day 3-4：第二阶段**
- 开发任务
- 阶段性交付
- 整体审查

**Day 5-6：第三阶段**
- 开发任务
- 阶段性交付
- 整体审查

### 阶段性审查内容

**技术审查：**
- 代码质量
- 架构合理性
- 性能指标
- 安全性

**产品审查：**
- 功能完整性
- 用户体验
- 业务逻辑
- 产品方向

**业务审查：**
- 业务需求匹配度
- 业务流程合理性
- 数据准确性

## 📋 审查流程

### 1. 每日晚间审查流程

```
18:00 - 自动触发审查任务
18:05 - 生成当日变更报告
18:10 - 开发工程师自查
18:20 - 产品经理审查
18:30 - Boss 审查
18:40 - 生成审查结果
18:50 - 调整明天任务（如需要）
19:00 - 发送审查报告
```

### 2. 每日晨会流程

```
09:00 - 产品经理和 Boss 开会
09:15 - 讨论产品方向
09:30 - 讨论模型变更
09:45 - 决策是否调整
10:00 - 发送变更通知（如有）
10:15 - 团队审查变更（如有）
10:30 - 调整任务分配（如有）
```

### 3. 阶段性审查流程（每2天）

```
Day 2 晚上：
- 阶段性交付
- 整体代码审查
- 功能演示
- 产品验收
- Boss 审批

Day 3 早上：
- 审查结果通报
- 问题修复计划
- 下阶段任务分配
```

---

## 🚨 问题处理机制

### 发现问题时

**轻微问题：**
- 当天修复
- 不影响进度

**中等问题：**
- 调整任务优先级
- 重新分配资源
- 延后部分功能

**严重问题：**
- 暂停当前任务
- 紧急会议讨论
- 重新制定方案
- Boss 决策

## 📊 审查标准

### 代码审查标准
```
✅ 代码规范：符合开发规范
✅ 功能完整：实现需求功能
✅ 测试覆盖：单元测试通过
✅ 性能达标：响应时间 < 500ms
✅ 安全合规：无安全漏洞
```

### 产品审查标准
```
✅ 需求匹配：符合产品需求
✅ 用户体验：交互流畅
✅ 业务逻辑：逻辑正确
✅ 数据准确：数据无误
✅ 文档完整：文档齐全
```

### 业务审查标准
```
✅ 业务流程：流程合理
✅ 数据准确：计算正确
✅ 合规性：符合财务规范
✅ 可用性：实际可用
✅ 扩展性：易于扩展
```

## 🎯 执行要点

### 关键原则
1. **自动化**：定时任务自动触发
2. **全员参与**：所有角色都要审查
3. **及时调整**：发现问题立即调整
4. **阶段交付**：2天一个周期
5. **文档记录**：所有审查都要记录

### 成功标准
- ✅ 每日审查按时完成
- ✅ 问题及时发现和解决
- ✅ 任务调整及时有效
- ✅ 阶段性交付按时完成
- ✅ 产品方向保持正确
